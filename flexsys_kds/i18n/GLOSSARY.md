# FlexSys KDS — Translation Glossary (Arabic)

`i18n/ar.po` already contains working Arabic translations for every
Python-side runtime message (the `_()`-wrapped strings — errors,
notifications, audit log notes). That file is safe to import as-is via
**Settings > Translations > Import Translation**.

This glossary covers everything *else* that is translatable but that I
could not safely package into a ready-to-import `.po` file without a live
Odoo 19 instance: Selection field option labels (Odoo auto-generates
`ir.model.fields.selection` external IDs for these, e.g.
`selection__kds_order__state__new` — the exact naming has shifted slightly
across versions, and shipping a guessed ID risks a silent no-op import
rather than a loud error) and the frontend's `_t()`-wrapped JS strings
(these live in `static/src/js/kds_i18n.js` and are extracted by Odoo's own
JS-scanning exporter, not by hand).

## Recommended workflow to finish this properly

1. Install the module on your Odoo 19 instance.
2. **Settings > Translations > Languages** → activate Arabic (`ar`) if not
   already active.
3. **Settings > Translations > Export Translation** → module `FlexSys
   KDS`, language `Arabic`. This produces the *authoritative* `.pot`/`.po`
   with correct xmlids for every selection label, view string, menu name,
   and JS string, generated by Odoo itself rather than guessed.
4. Open that exported file and fill in `msgstr ""` using the tables below
   (the `msgid` values will match the English text you see here exactly,
   since I wrote all of it).
5. **Settings > Translations > Import Translation**, pick Arabic, upload
   the completed file.
6. Every user whose `res.users.lang = ar_001` (or another Arabic locale
   already in Odoo) will then see the KDS screen and backend both in
   Arabic, RTL-mirrored automatically.

You can of course substitute any other language the same way — this
glossary's structure (English source → suggested translation) works the
same regardless of target language; only the Arabic column below is
filled in.
