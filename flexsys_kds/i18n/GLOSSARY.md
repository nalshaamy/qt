# FlexSys KDS — Translation Glossary (Arabic)

`i18n/ar.po` now contains working Arabic translations for every
Python-side runtime message (the `_()`-wrapped strings — errors,
notifications, audit log notes) **and**, as of the "Arabic Backend
Finalization" sweep, every view field label/help text (form, list,
search), selection option label, and remaining view/menu string swept
across the module's own backend screens (Stations, Routing, Printers,
Print Jobs, Printer Hub, Orders, Events, POS Config Settings, Product
views, and the module's own menus). That file is safe to import as-is
via **Settings > Translations > Import Translation**.

The tables below remain the authoritative terminology reference and
are kept up to date — but the file no longer needs a live Odoo
instance's own export to complete the coverage described in the
"Recommended workflow" section further down; that workflow is
preserved here only as a reference for how the entries below were
originally scoped, and as the correct process for verifying/importing
`ar.po` on your own instance, or for any *future* string this module
gains that isn't in `ar.po` yet.

LOCALIZATION ARCHITECTURE UPDATE ("Arabic Localization & RTL
Specification"): the Internal KDS Screen's own operational labels
(`static/src/js/kds_i18n.js`) and the Public Kiosk's own operational
labels (embedded in `controllers/kds_kiosk.py`) do **not** use Odoo's
shared `_t()`/translation-catalog mechanism at all — a confirmed
collision with Odoo's own core Arabic catalog (`_t("NEW")` silently
matching an unrelated core translation) made that approach unsafe, per
that fix's own documented root cause. Both screens instead use a
small, self-contained bilingual dictionary (`KDS_LABELS_EN`/
`KDS_LABELS_AR` for the Internal Screen, selected by the logged-in
user's own language; `KIOSK_LABELS_EN`/`KIOSK_LABELS_AR` for the
Public Kiosk, selected by the station's own `kiosk_language` field) —
**not** extracted by Odoo's own translation exporter, and not
importable via `.po`, and **out of scope for the Backend Finalization
sweep** (that sweep covers Odoo's own standard backend screens only —
Configuration/Operations/Analytics menus — not the Internal Screen or
Kiosk, which have their own separate, already-complete Arabic
dictionaries). To change or extend these labels, edit those two
dictionaries directly; the tables below document their current values
for reference and for keeping the two screens' own terminology
consistent with each other and with the backend.

This glossary covers everything *else* that is translatable but that I
could not safely package into a ready-to-import `.po` file without a
live Odoo 19 instance: Selection field option labels (Odoo
auto-generates `ir.model.fields.selection` external IDs for these,
e.g. `selection__kds_order__state__new` — the exact naming has shifted
slightly across versions, and shipping a guessed ID risks a silent
no-op import rather than a loud error) and view/menu labels (also
extracted by Odoo's own exporter, not by hand).

## Recommended workflow to finish this properly

1. Install the module on your Odoo 19 instance.
2. **Settings > Translations > Languages** → activate Arabic (`ar`) if not
   already active.
3. **Settings > Translations > Export Translation** → module `FlexSys
   KDS`, language `Arabic`. This produces the *authoritative* `.pot`/`.po`
   with correct xmlids for every selection label, view string, and menu
   name, generated by Odoo itself rather than guessed. This export will
   NOT include the Internal Screen/Public Kiosk operational labels (see
   above) - those are edited directly in their own JS/Python source.
4. Open that exported file and fill in `msgstr ""` using the tables below
   (the `msgid` values will match the English text you see here exactly,
   since I wrote all of it).
5. **Settings > Translations > Import Translation**, pick Arabic, upload
   the completed file.
6. Every user whose `res.users.lang = ar_001` (or another Arabic locale
   already in Odoo) will then see the backend in Arabic, RTL-mirrored
   automatically, and the Internal KDS Screen in Arabic via its own
   dictionary (same language source, `user.lang`). A station's own
   Public Kiosk language is set independently, per station, via its own
   `kiosk_language` field (Station form → Public Kiosk tab) - there is
   no logged-in user on the public kiosk to read a language from.

You can of course substitute any other language the same way — this
glossary's structure (English source → suggested translation) works the
same regardless of target language; only the Arabic column below is
filled in.
