QT Cafe QR Order - Consolidated Change Notes
=================================================
هذا الملف يجمع سجل التعديلات السابق للموديول حسب تسلسل الإصدارات.
الإصدار الحالي: 19.0.16.17.0

========================================================================================
V6_NOTES.txt
========================================================================================
V6 - POS Config Routing
- Added Default POS setting for QR orders.
- Added pos_config_id on QR orders.
- QR URL can route to specific POS: /qr-menu?pos_config_id=<POS_CONFIG_ID>
- Pending POS alert endpoint can filter by pos_config_id.
- Added helper note inside POS Config form.

========================================================================================
V7_NOTES.txt
========================================================================================
V7 - Load QR Order to POS
- Adds QR Orders button in POS control buttons.
- Fetches pending QR orders for current POS config.
- Loads first pending QR order into a new POS order with products, qty and price.
- Marks QR order as loaded/accepted to prevent duplicates.
- Adds QT Cafe → Configuration → Settings shortcut for Default POS.

========================================================================================
V7_1_NOTES.txt
========================================================================================
V7.1 - Concurrency/Double Click Fix
- Mark loaded endpoint is idempotent.
- Duplicate accepted/loaded updates return success instead of failing.
- POS QR Orders button has a click guard to reduce duplicate requests.
- Addresses: could not serialize access due to concurrent update.

========================================================================================
V7_2_NOTES.txt
========================================================================================
V7.2 - Registry Fix
- Fixed wrong menu external ID in QT Cafe settings menu.
- Parent menu corrected from menu_qtcafe_qr_order_config to menu_qtcafe_config.
- Simplified POS config view extension to avoid fragile POS form inheritance during registry loading.

========================================================================================
V8_NOTES.txt
========================================================================================
V8 - Auto Create Backend POS Order
- QR order now stores pos_config_id from the QR link/default setting.
- When customer submits a QR order, the module tries to create a real backend pos.order in the open POS session.
- Accepting a QR order also creates the POS order if it was not created yet.
- QR order form includes manual Create POS Order fallback.
- This is intended to make the order visible in POS Orders/Ticket screen, not just show the alert.

========================================================================================
V10_NOTES.txt
========================================================================================
V10 - QR Number in POS
- POS orders created from QR orders now use the QR order number in name and pos_reference.
- This prevents POS order list from showing false for QR-originated orders.

V11 Registered Customer / Guest

V15_MULTI_BRANCH_NOTES.txt
========================================================================================
V15 Multi Branch / Nearest POS
- Multiple POS configurations can be enabled as QR branches.
- Each branch has name, address, latitude, longitude, open/closed state and maximum distance.
- Customer can grant browser geolocation and branches are sorted nearest-first using Haversine distance.
- No Google API key or billing is required.
- Selected branch is saved as pos_config_id and the QR order goes only to that POS.
- Dashboard shows branch status and can open/close each branch independently.
